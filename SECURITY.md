# Reporting a security concern

**English — main** · [Italiano](SECURITY.it.md) · [Deutsch](SECURITY.de.md)

**Please do not disclose suspected vulnerabilities, credentials, or private data in public GitHub issues, discussions, or pull requests.**

## Private contact

Email [contact@toolavio.com](mailto:contact@toolavio.com?subject=Toolavio%20security%20report) with the subject **Toolavio security report**.

Start with a minimal description of the issue, the affected public URL or feature, the observed impact, and safe steps to reproduce using synthetic data. Include the approximate time, browser, and operating system when relevant.

Do not attach private user documents, credentials, authentication cookies, payment information, or proprietary software archives. Ordinary email should not be treated as an end-to-end encrypted channel; describe the concern first and discuss an appropriate way to provide sensitive material if necessary.

## Safe reporting

Use only your own test data and accounts. Do not access other users' data, disrupt service, perform destructive testing, or continue testing after encountering information you are not authorized to access. This document does not grant permission for intrusive testing or access beyond your authorization.

## Scope and expectations

This repository publishes documentation, not Toolavio's application source. Reports may concern the public service, incorrect privacy behavior, or accidental disclosure in the documentation.

This page does not establish a bug-bounty program, guaranteed reward, response-time commitment, or security certification. Public documentation must not expose implementation details that could make an unresolved issue easier to exploit.
