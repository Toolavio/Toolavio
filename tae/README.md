# Toolavio Action Engine — PDF Alpha · Build1

**English — main** · [Italiano](README.it.md) · [Deutsch](README.de.md)

**Five PDF tools for an embedded workspace, with simpler client and website management.** Toolavio Action Engine (TAE) is the integration project behind Toolavio Action. Its permanent application path is `https://toolavio.com/tae/`.

> **Status: PREPARED — private integrated build, not a hosted production release.** This GitHub update publishes documentation and the matching embed loader only. It does not deploy or activate TAE on Toolavio.com. Review in the original development environment and the remaining release checks must be completed before availability is announced.

## Five tools, all PDF

| Tool | What it does | Optional `data-tool` |
| --- | --- | --- |
| **Merge PDFs** | Combine documents in the selected order. | `merge-pdf` |
| **Extract pages** | Create a PDF from selected pages. | `extract-pdf` |
| **Remove pages** | Remove the specified pages. | `remove-pdf` |
| **Rotate pages** | Rotate all pages or a selection. | `rotate-pdf` |
| **Reorder pages** | Change the page order or reverse the document. | `reorder-pdf` |

These operations work on PDF pages without rasterizing them into images. Compression, OCR, redaction, image conversion, and text rewriting are not included in this TAE scope.

The previous CSV/JSON/image Alpha selection is replaced **only in TAE**. Toolavio's main website keeps its own catalog; Toolavio Pro and PDF Studio remain separate offerings. The standalone Toolavio Core data-module initiative is also separate from this PDF Alpha.

## A simpler operator panel

The prepared panel starts with **Your sites → Add site**, rather than a technical configuration form:

1. Select or create the client and enter the website address.
2. Choose the PDF tools to enable.
3. Follow the DNS domain-verification instructions and activate the installation.
4. Copy its integration code and give it to the website owner.

The site card provides code copying, tool selection, editing, and suspension. Technical identifiers, extra origins, expiry, and the activity log are placed in advanced settings.

After the initial server/database setup, ordinary client and site changes are read from the database without a new application build or server restart. This behavior was covered by local HTTP/SQLite tests; the production MySQL check remains open. Code changes and server configuration still require the appropriate release or restart process.

This is a **single-operator management panel**, not a customer self-service portal or subscription billing system. Domain authorization is not a paid-license system or DRM. Suspending an installation does not cancel a subscription or delete results already downloaded.

## Embed example — after deployment and site activation

Use the code generated by the operator panel. The placeholder below is not an active installation ID.

```html
<div id="toolavio-action"></div>
<script
  src="https://toolavio.com/tae/embed.js"
  data-container="toolavio-action"
  data-site-id="REPLACE_WITH_SITE_ID_FROM_ADMIN"
  data-lang="en"
  data-tool="merge-pdf"
  async>
</script>
```

**Do not paste an administrator password or session secret into this snippet.** The site ID is a public identifier, not a password. The hosted runtime checks the installation's configuration and authorized embedding origins.

`data-lang` supports `en`, `it`, and `de`, with English as the default. `data-tool` is optional and selects one of the five PDF tools; it does not grant access to a tool disabled for the site. Use a distinct container ID for each instance.

[View the HTML example](example.html). Serve the host page over HTTP/HTTPS, not a chat preview or a `file:` URL. The host's security policy must permit the required Toolavio script and frame; the Toolavio installation must authorize the exact website origin. Copying this loader alone does not install the private application or enable the service.

## Processing and limits

PDF processing runs in the browser. Loading resources and checking installation access still require server requests. This TAE build does not promise offline operation, universal CMS support, or native app installation.

Prepared limits: **up to 10 files, 64 MiB combined, and 300 pages**. Documents with detected encryption, interactive forms, or signature permissions are rejected. Detection is not cryptographic signature validation. Bookmarks, attachments, annotations, metadata, signatures, and other complex structures are not universally guaranteed to survive unchanged. Keep originals and inspect important results.

The loader uses a sandboxed frame and checks message origin, frame window, and instance channel for readiness and resizing. It does not forward document contents or results to the host through that protocol. Browser-delivered JavaScript remains inspectable.

## What has and has not been verified

The private Build1 preparation report records local module/HTTP tests, offline Chromium interface tests, and independent checks of sample PDF content, page order, rotations, and pixels. Browser interface tests use synthetic authorization or administration responses and an offline harness. **They are not end-to-end production proof.** This documentation update does not rerun or extend that software validation.

Before activation, the open checks are isolated MySQL testing, normal HTTP/HTTPS browser loading and cross-origin embedding, regressions in the original Toolavio environment, an authorized deployment, and a live post-deployment check. No WordPress, Shopify, Safari/iPhone, or Android compatibility certification is claimed.
